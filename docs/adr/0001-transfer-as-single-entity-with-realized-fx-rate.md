# Transfer is a single entity with two legs, not two linked Transactions

Money regularly moves between Accounts held in different currencies (e.g. USD → INR). The obvious alternative — plain double-entry bookkeeping, where a transfer is just two independent Transactions (a withdrawal and a deposit) that happen to reference each other — was rejected. Instead, `Transfer` is modeled as one entity with a source leg and a destination leg, each in its own currency, carrying the FX rate actually realized on that move. This keeps both sides atomically linked and captures the real exchange rate obtained (rather than an assumed market rate), which is itself data the reconciliation process needs — a rate that's off is as much a signal as a missing Transaction. Any wire fee or FX spread is absorbed into this realized rate rather than tracked as a separate line item.
